# ADR-0001：IMA 目录级 RAG 与运行时自动路由

- 状态：已采用
- 日期：2026-07-31

## 背景

IMA 是用户的云端知识库，全文检索和回答由 IMA 服务端完成。仅在系统提示词中要求 agent 使用 IMA 属于软约束；当 MCP 工具较多并启用渐进发现时，模型可能直接凭记忆回答，或者改用其他法律数据库，必须由用户再次强调“查询 IMA”。

IMA 的 Cookie 接口能够返回知识库名称、简介、推荐问题、文档标题、摘要、标签和文档数量，但 Legalwork 不应复制用户的完整云端内容建立第二套全文索引。

## 决策

采用两级检索：

1. Legalwork 对 IMA 返回的有限目录元数据执行轻量目录级 RAG，计算候选库得分与路由置信度。
2. 高置信度问题只查 Top-1；候选库得分接近或复合研究问题最多查 Top-2。零匹配时不得任意选择目录中第一个库。
3. 选库后调用 IMA 问答接口，由 IMA 对库内全文执行最终检索和生成。Top-1 明确返回未命中时，只允许向下一个正分候选库回退一次。

IMA MCP 提供统一的 `research_ima(question)` 工具，将“读取目录、置信度选库、有界全文问答”封装为一次调用。Agent 不应在正常路径中先调用 `list_available_knowledge_bases`。目录元数据可在进程内缓存 60 秒，缓存与登录凭据指纹绑定，不缓存 Token、Cookie、原始响应或问答正文。

Legalwork 运行时对知识密集型法律任务执行确定性路由：

- 尊重“不要使用 IMA”及“只使用指定来源”等用户约束。
- 直接模式只向模型开放 `research_ima`。
- 渐进 MCP 模式先强制发现 `ima-knowledge-base/research_ima`，再强制调用。
- 如果模型未执行本步唯一工具，运行时自动补发同一只读调用。
- IMA 无匹配或不可用时，继续使用国家法律法规数据库、北大法宝、元典或本地知识库。

## 备选方案

### 只增强系统提示词

实现简单，但不能保证模型执行，已经出现漏调用。

### 将 IMA 全文同步到本地向量库

能够统一检索，但重复 IMA 的全文 RAG，带来同步延迟、存储成本、权限漂移和云端资料落地风险。

### 每次查询所有知识库

召回率高，但会产生大量 IMA 会话记录、延迟和无关答案，且难以解释来源。

## 影响与权衡

- 优点：用户无需点名 IMA；单一问题通常只产生一次主要知识库问答；跨库风险明显时最多扩展到两库；路由结果可解释；不复制云端全文。
- 局限：目录级检索依赖名称和元数据质量，语义非常隐晦时可能选错库。用户仍可显式传入知识库 ID 覆盖。
- 性能：自动流程通常增加一次目录请求；60 秒元数据缓存可吸收紧邻调用；Top-2 问答并行且严格限制为两库。目录读取失败时可回退登录快照。
- 安全：目录索引只保留有限元数据，不记录 Cookie、Token、原始 SSE 或全文；工具结果沿用 MCP 凭证脱敏规则。
- 失败模式：IMA 未连接、认证过期、目录无结果、问答无匹配或协议变化时，不阻断其他权威法律来源。
